## 3. 费用停止机制

参考 [LiteLLM 官方预留与失败关闭机制](https://docs.litellm.ai/docs/proxy/users#budget-reservation)：跨供应商费用需要统一准入、持久记账与可靠费率。完整 LiteLLM 预算还需 Postgres 等服务，本单实例候选使用已有 FastAPI/httpx 与标准库 SQLite 实现窄范围预算入口，不额外引入大型路由系统或修改现有 Sub2API。

金额统一为整数 micro-USD，累计限额固定 **10,000,000 = USD10**。一份持久账本涵盖 GPT、DeepSeek、Qwen、重试、标题/压缩等辅助调用，所有会话共享；无按日、重启、模型或会话自动恢复额度的行为。

费用预留采用供应商实际执行的完整输入上下文上界与请求输出上限：`ceil((最大输入token×输入费率 + 输出上限×输出费率) / 1,000,000)`，费率单位为 micro-USD/百万token。完整输入上界包括消息、函数定义、模板等 token，避开未知别名的本地分词误差。保守预留可能使试点提前停止，不能承诺正好花满 USD10。

| 情况 | 行为 |
| --- | --- |
| 正常调用 | SQLite BEGIN IMMEDIATE 原子预留，最多一路在途；预留持久化后才发送 |
| 正常 usage | 依已确认的峰值费率向上取整结算，释放未用预留 |
| HTTP错误、超时、缺usage、断流无DONE | 按整笔预留计账，不视为免费，不自动重发 |
| 到达或无法覆盖下一笔预留 | 持久锁定全局停止，后续所有路由返回402且不转发 |
| 进程崩溃留下在途记录 | 保留预留，下次启动拒绝，等待审查；不按TTL退还 |
| DB缺失/损坏、策略摘要变更、过期/未知费率 | 失败关闭；运行启动不会创建空账本 |
| usage超出确认上界 | 保留未结算记录并阻止继续，不以低估费用退款 |

此机制对**真实费率、额外收费和供应商执行上界的确认**有明确前提。供应商改变账单规则或不遵守已确认输出/上下文限制时，本地代码无法撤销已经发生的费用。不能将错误费率、余额轮询或事后通知包装成无条件财务硬上限。部署前要确认别名实际计费、所有缓存/时段/隐藏reasoning类别及无额外请求费用；可用时再用专属供应商 key/cap 加强隔离。本批没有创建或修改这些凭据或限额。

DeepSeek 暂按 [官方峰值定价](https://api-docs.deepseek.com/quick_start/pricing/)：输入缓存未命中 USD0.30/百万token、输出 USD1.20/百万token，不依赖缓存或低峰折扣。对文档1M上下文保守取1,048,576输入token，输出限4096，初步单次上界 USD0.319488；执行策略冻结时还须确认该精确上下文限制。[输出及usage契约](https://api-docs.deepseek.com/api/create-chat-completion/)

GPT/Qwen 的实际节点仍为用户确认的 `https://ccnode.briconbric.com:49530/v1`。共享网关账面余额和倍率1不包含完整单价证明，也无法证明 Qwen GGUF 别名的容量/收费。本轮公开价格查询403后未猜测管理端点、申请管理员权限或修改服务。价格模板将这两路设为未确认，验证与启动必须阻断。Qwen 不要求另开 Model Studio 账号。

## 4. 调用及权限边界

未来 Hermes 的三路 base URL 分别指向预算入口 `/gpt/v1`、`/deepseek/v1`、`/qwen/v1`，使用同一入口凭据；上游仍为已验证公网服务与 DeepSeek 官方。主调用、重试和辅助调用都必须走此入口。仅支持文本 Chat Completions 和本地模型目录，Responses/Anthropic/WebSocket/batch、图像/语音及服务商内置搜索/OCR/文件工具均拒绝；这些付费能力不会从未计价路径绕过。

入口保存真实上游 key、价格策略及账本，Hermes 仅持有不同的入口凭据。计划使用受控网络命名空间连接、独立进程/文件命名空间，不给 Hermes 挂载账本、管理员策略、上游 key、docker.sock 或恢复材料。当前服务端只绑定 loopback，具体容器网络连接、挂载和防绕过效果仍需 B1 真正运行验收。

全局停止阻止新增付费请求；已发送请求已有预留，不承诺撤销其供应商计费。入口不杀宿主进程。Hermes 收到402可能沿备用链继续询问，同一停止账本会拒绝转发，不再产生付费请求。停止后的任务应保留检查点，禁止通过删除数据库、改pilot_id或换 key 继续同一试点。
