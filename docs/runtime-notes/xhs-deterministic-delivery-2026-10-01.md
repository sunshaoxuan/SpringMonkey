# 小红书草稿与文档访问修复

## 本次确认的需求

- 用户授权修复定期推荐文及每次交付链接的访问问题，并指定自己的 Google 收件账号。
- 账号只进入主机受保护配置 `OPENCLAW_OWNER_GOOGLE_EMAIL`，不进入 Git、模型提示词或交付日志。
- 创建者可以使用当前已登录的 Google 账号；收件者使用已获授权的账号打开文档。
- 文档保持受限访问，只授予查看者；禁止公开共享、编辑权限和所有权转移。
- 每份新文档都检查指定收件者的权限，后续访问请求使用相同确定性检查。
- 本任务只产出供确认的草稿，发布小红书需要用户另外确认。

## 执行与成功标准

1. 复用已有独立私聊投递器，独立于研究模型发送成功或失败结果。
2. 停用原生 XHS 定时任务，保留历史，系统 cron 成为唯一调度来源。保留原日期规则 `0 10 */3 * *`，已核验主机为 Asia/Tokyo。这是按月日期步进，并非严格间隔 72 小时。
3. 专用研究 agent 使用 web_search/web_fetch，以及唯一获准执行的公共素材读取器。素材工具限定公共来源域名，返回最多 7000 字符，提供真实搜索链接、渲染后商品信息与图片 URL；读取仅限研究工作目录，逐图核对包装及水印，禁止任意 shell 命令和私人 Google 页面。研究限时 1200 秒，输出小型 JSON 清单及核验来源。主模型认证及全局 provider 保持原配置。
4. 图片入口验证公共 HTTPS、来源、同版本声明、数量、MIME、尺寸、大小和重复内容；使用 python-docx 创建正文与嵌入图。
   图片通过无登录态 HTTP 下载，允许官方来源使用公共 CDN；带登录态的浏览器页面读取仍受来源域名及账号路径限制。清单哈希绑定实际看过的图片，入稿下载后再次核对哈希。
5. 使用现有已登录浏览器确定性导入 DOCX，导出后独立比较完整正文与至少三张不同的嵌入图。
6. 共享给受保护配置中的账号，重新打开保存后的共享界面，确认精确账号为查看者且常规访问受限。
7. 只有上述检查通过才写 verified 凭据及最新文档登记。导入后先记录 URL，重试复用同一文档；进程锁避免并发。
8. 失败时返回非零状态，由独立投递器通知；通知未实际发送时记录失败，不伪记已投递。

## 修复入口

- 主机执行 `scripts/openclaw/install_xhs_delivery.py`。本地通过 `scripts/remote_install_xhs_delivery.py` 调用已拉取版本的安装入口。
- 旧 `remote_fix_xhs_cron_model.py` 已移除，避免再次启用原生调度和模型操作权限。
- 手动执行入口迁移到独立投递器；状态查询保留原生历史并显示系统 cron 的实际执行记录。
- 恢复服务固定 `HOME=/var/lib/openclaw`，使用官方任务来源，回查七天并按任务 ID 去重，移除不存在的 jobs.json 安装参数。
- 官方目录包含停用任务以正确关联旧失败；恢复流程尊重任务停用状态，不重跑已迁移的原生任务。
- 实际补跑发现浏览器清理器把 iframe 当作标签并关闭工作页面。守护脚本只统计 page，文档操作与清理器共享进程锁；锁随进程退出释放。上传后处理新开的文档标签，只关闭本流程创建的标签，不清除登录状态。
- Google Docs 共享区使用分裂按钮；明确选择主共享按钮，避开快捷菜单。权限核验使用独立的新页面，避免沿用操作窗口状态。
- 商品图库可能位于文章或 main 容器之外；通过浏览器完整图片定位器提取并优先返回标题相符的商品图，仍遵守固定返回预算。失败清单保留为诊断状态，重试重新研究，不把失败 JSON 当作草稿缓存。

## 验证记录

- 实际宽泛搜索命中了允许列表之外的来源，因此返回空候选；搜索范围现限定到可读取的官方及日本实拍来源。研究最多 6 次搜索、8 次页面读取，维持单次 7000 字符及整轮超时，支持最多三个候选切换。
- 实拍下载故障已用独立请求定位：同一 Ameba 图片 URL，默认请求及仅 Referer 均为 403；仅添加普通浏览器 User-Agent 即为 200、image/jpeg。统一下载函数增加该标识，仍不携带 cookies 或账号认证，每次重定向继续核对公共地址。
- 搜索先提取标题结果，再按允许来源筛选和去重，最后限制 15 个链接。原先先取 40 个导航链接可能挤掉实际商品结果；已增加超过 40 个无关导航的回归用例。
- 10 月 1 日已有草稿补交成功。实际 Google Docs 导出与原 DOCX 全文一致，包含三张不同嵌入图，话题各占一段。重新打开共享界面确认指定收件人为查看者、常规访问受限；9 月 25 日历史文档权限也已核验。
- 实际 Discord 私信成功，记录为 `delivery=delivered`、`sentChunks=1`。此前失败也真实发送了失败通知。
- 新选品验收仍在进行。最近一次失败是选择了缺少同款实拍证据的草莓蛋白饮料，搜索命中了其他酸奶产品，因此正确拒绝入稿。研究顺序改为先确认日本实拍，再匹配官方同款；保留候选切换预算。素材压缩优先删除导航链接，避免挤掉商品图片。
- 模拟测试不能替代真实 Google Docs 与 Discord 验收。研究清单中的真实性及无水印声明需来源证据支撑，程序的格式检查不构成图片版权许可。
